# SPEC-0016 · DSH 超级管家基础与飞书入口

状态：Implemented / locally verified · 2026-10-13；飞书 live not_run。用户授权工程重组与基础建设；Dots、Muse 仅作产品例子，不接具体外部 Agent。

## 目标与范围

lumi 成为可在单台服务器部署的个人管家外壳。DSH 唯一拥有推理、规划、Session、工具与子 Agent 调度；本仓维护 SDK 启动、个人插件、通道、设备及协议扩展。P0 打通飞书单 owner 私聊文本入口，App 留待后续。

| ID | 需求与验收 |
| --- | --- |
| FR-01 | DSH 发行包统一升级至 0.2.0-rc.2；旧保护性验收继续通过，显式新鲜度检查可运行 |
| FR-02 | 新服务器通过官方 SDK 启动持久 DSH；通道插件调用 DSH 原生 Agent create/resume/input/cancel，不实现新的推理或派单循环 |
| FR-03 | 飞书官方长连接接收事件，校验应用、owner open_id、私聊和文本；未授权输入不进入模型，不产生回复 |
| FR-04 | 持久收件箱按平台 message_id 去重；先落盘再返回事件回执；处理串行，DSH Session 映射可跨进程恢复 |
| FR-05 | 发送前保存回复意图，成功保存平台 message_id；发送结果未知不能自动重发；进程中断的模型请求不能自动重放 |
| FR-06 | 支持帮助、新会话、取消；取消与新会话的语义由 DSH 原生控制实现，不伪称撤销外部副作用 |
| FR-07 | 插件默认只开放对话和个性化状态工具；外部 Agent、文件/Shell/网络执行与高风险动作需未来能力规范，不由飞书身份自动授权 |
| FR-08 | 明确工程职责、旧路径退役条件、升级/备份/回滚与部署步骤；保护旧数据库、用户未提交 SVG 和历史验收 |
| FR-09 | 密钥不进入 Git、日志、模型、默认 SDK 子进程环境或 fixture；只有可信通道插件取得专用飞书配置 |

## 影响与兼容

- 新默认启动路径为服务器，旧 Gateway/CLI/Workbench 以明确 legacy 命令保留。旧 Task/Action/Memory/Reminder 数据不迁移、不删除。
- 保留可用个人记忆领域模块及可迁移快照；新入口只读取显式选择的快照，不自动读取旧库或自动写入记忆。
- 删除被新入口替代的默认文档叙述及重复目录说明；完整旧操作说明归档为兼容 SOP，不以删测试方式制造精简。
- 插件源码与依赖升级、默认命令改变需同步 README、AGENTS、事实、ADR 与架构检查。

## 非目标与验证界限

不接 Dots/Muse、任意 A2A 服务或具体设备；不做自研 Agent 编排、周期自主调度、自动升级线上进程、App、群聊、多实例、附件、逐 token 输出或通用审批系统。

本机完成真实 DSH + 官方 mock 模型的会话/恢复/权限验收，以及飞书事件和发送协议的离线验证。真实飞书需用户提供专用应用凭据并完成平台启用；在收发实测前状态为 Implemented / live not_run，不宣称已上线。
