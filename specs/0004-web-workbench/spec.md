# SPEC-0004：本地 Web 工作台

状态：Implemented / verified_once · v0.1 · 2026-09-25。

## 用户结果

用户可以在电脑浏览器中直接使用 lumi：提交任务、查看运行状态和执行记录、处理已有任务级审批、取消任务，并读取最终结果。界面连接 lumi Gateway，不绕过 Core、Ledger 或 DSH adapter。

## 范围

- 新增 React + Vite 单页工作台，由仓库独立 workspace package 管理。
- 使用现有 `/health`、`/v1/capabilities`、`/v1/tasks`、事件、审计及 approve/reject/cancel API。
- 任务 ID 由客户端在提交前生成；POST 等待期间通过 GET 轮询当前状态。
- 生产构建由 Gateway 同源托管；开发态由 Vite 代理 `/v1` 和 `/health`。
- 支持桌面与窄屏布局、连接异常、空状态、加载状态和操作失败反馈。

## 非目标

- 不把 DSH Web UI 嵌入或改造成 lumi UI。
- 不实现产品级多轮 Conversation、流式 token、SSE/WebSocket、系统托盘或原生安装包。
- 不扩大当前审批语义；页面只能如实呈现现有任务级审批。
- 不实现 SPEC-0001 的参数级 Action Broker，也不宣称当前工具动作已被全面门禁。

## 功能需求

| ID | 行为 |
| --- | --- |
| FR-001 | 首屏直接显示任务工作台，不使用营销落地页。 |
| FR-002 | 用户可提交非空任务，客户端生成稳定 ID，并立即进入该任务详情。 |
| FR-003 | 工作台定期刷新任务、当前任务、事件和审计；刷新失败保留已有数据并提示。 |
| FR-004 | 待审批任务显示风险与原因，并允许批准或拒绝；非终态任务允许取消。 |
| FR-005 | 完成、失败和取消状态显示实际结果或错误，不把 HTTP 成功等同于任务完成。 |
| FR-006 | Web 构建可由 Gateway 同源提供，API 不需要开放 CORS。 |
| FR-007 | UI 不展示或持久化模型密钥，不读取 `.env` 内容。 |

## 验收

| AC | 验收条件 |
| --- | --- |
| AC-001 | 使用 mock executor 启动 Gateway 与 Web，浏览器可提交任务并看到 completed 结果。 |
| AC-002 | 提交需要审批的任务后，页面显示 waiting_approval，批准或拒绝会刷新最终状态。 |
| AC-003 | 运行中任务可取消；终态任务不显示取消操作。 |
| AC-004 | 任务事件与审计记录可在详情视图切换查看。 |
| AC-005 | API 不可用时页面呈现连接错误且不丢弃已加载任务。 |
| AC-006 | `pnpm check` 通过，生产构建包含 Gateway 和 Workbench。 |
| AC-007 | 桌面和移动宽度无重叠、裁切或横向溢出，实际浏览器截图通过检查。 |

## 边界

本切片提供可用入口，但不改变现有安全结论。Gateway 仍仅适合 loopback，HTTP actor 仍是请求字段，任务执行仍是进程内异步过程，进程重启不会自动恢复运行中任务。这些由 SPEC-0001 及后续恢复切片处理。
