# SPEC-0014 · DSH 原生定制路线评估

2026-09-26 · 状态：设计整理与文档检查完成（verified_once）；运行方案 Proposed，全部迁移实验 `not_run`。

用户希望结合 DSH 的真实插件机制，判断是否应直接基于 DSH 二次开发。此前明确暂不修复 lumi Workbench。本切片仅交付方案、源码依据、迁移门槛和决策记录；不修改业务代码、依赖、运行 profile 或数据库，不启动或切换服务。按既有授权完成文档验证后提交并推送当前跟踪分支。

本次合并记录设计范围、计划、检查项和证据。后续实现涉及协议、权限或持久化变化，必须另建完整 spec / plan / tasks / checklist / evidence，不能用本次设计验收代替运行验收。

## 目标与影响分析

| 要求 | 交付落点 |
| --- | --- |
| FR-001 比较外部插件定制、源码 fork 和现有外壳 | [主方案](../../docs/design/11-dsh-native-customization.md) §1，推荐外部 bundle，必要时薄补丁 |
| FR-002 依据真实接口判断可行性 | 主方案 §3–4：固定源码、发行版差异、Web / Preset / Remote 构建限制 |
| FR-003 明确已有实现去留 | 主方案 §5：复用领域服务，逐步退出重复入口及 SDK 包装，不丢资产与事务 |
| FR-004 给出可否决的验证顺序 | 主方案 §6：P0 外部安装与多轮对话，P1 记忆与动作，P2 切换与回滚 |
| FR-005 状态和文档一致 | [ADR-005](../../docs/adr/0005-dsh-native-customization.md)、导航、现状及旧方案入口 |

影响：

- 候选运行结构由“独立 lumi Runtime 启动 DSH 子进程”转为“DSH Host 装配 lumi 服务”。这是待验证的运行所有权变化，ADR-004 继续记录现行 v0.1。
- 个人资产仍由 lumi 领域模块拥有。插件可以提供长期存储服务；进程位置与数据主键、Schema 所有权分别决定。
- 普通对话拟直接复用 DSH Session；需要跨轮次承诺、授权和验收的工作保留业务 Task / Action。TaskExecutor、Action→Task 依赖、执行引用和恢复机制须在实现 spec 中处理。
- 当前 `adapters/dsh` 依赖边界仍生效；未来允许 DSH 类型进入具体 `plugins/dsh-lumi` 接线层，需要同步架构门禁和升级契约，领域包继续不依赖 DSH。
- 原工作台、CLI、Gateway、数据库和运行中服务保持当前状态；本次无运行时迁移或飞书发布。
