# SPEC-0001：最小动作门禁与可核验交付

状态：Implemented / locally verified · v0.2 · 2026-09-25。已实现并通过本机验收，未远端发布；范围仍仅限受控 `artifact.write`，不代表 DSH 任意工具已接入门禁。

关联：[M1 路线](../../docs/design/07-roadmap.md)、[ADR-002](../../docs/adr/0002-actions-and-evolution.md)。

## 问题与用户结果

当前任务审批只基于文字与 capability 风险。执行器可在运行中生成任意工具参数，Core 收到非空结果即可完成。用户无法依据任务级批准确定哪个目标真的改变，也无法区分“动作失败”和“发生了但回执丢失”。

本切片使用户能审阅一个具体动作，在限定范围执行，并通过真实本地文件与读回证据判断结果。审批后参数变化、撤销或重复执行都不能静默绕过。

## 范围

包含：本地单 owner 身份绑定、版本化动作/授权/回执、SQLite 事务记录、规范化幂等、确定性策略、单个受控 `artifact.write` 动作、读回验证、未知结果状态、CLI/HTTP 共享服务、旧 v1 行为兼容。

最小动作仅在新建的专用测试根目录创建文件；不覆盖用户现有文件，不访问网络。参数是受控 artifact ID、内容摘要和内容引用；执行代理确定实际路径，模型不能传任意绝对路径。产物使用原子创建与稳定 action ID 关联，可按 ID 对账。

不包含：完整 MCP/A2A/plugin host、全量 DSH shell 门禁、OS 通用沙箱、持久 scheduler、记忆系统、多设备、外部消息/支付/设备写入、自动发布。DSH 任意工具路径在 M1.3 另行验收；本切片成功不能宣布所有工具已受控。

## 功能需求

| ID | 行为 |
| --- | --- |
| FR-001 | CLI 绑定本机已配置 owner；HTTP 从认证配置映射 principal，拒绝请求体自报提权和跨 owner 查询/审批。具体本地令牌机制在 plan 固定。 |
| FR-002 | 准备 Action 保存不可变参数快照、摘要、capability 版本、目标、幂等键、时限和 effect，返回可审阅对象。 |
| FR-003 | 策略按身份、禁止项、数据、委托、参数、风险、预算顺序裁决；缺失或不兼容时拒绝，不由模型决定最终允许。 |
| FR-004 | Authorization 绑定动作摘要、owner/principal、能力版本、次数、时限和撤销 epoch；执行前重验并原子消费额度。 |
| FR-005 | 只有 action-runtime 的受控执行代理可调用 artifact provider；该 provider 不接受来自模型的任意文件路径。 |
| FR-006 | 同一语义请求重传与服务端时间无关；相同业务幂等键和相同摘要复用结果，不同摘要返回 CONFLICT。 |
| FR-007 | 调用前持久化意图，成功保存回执；远端/执行代理可能成功但账本未记时进入 outcome_unknown，先读回对账，不盲重做。 |
| FR-008 | 核验器检查实际文件、摘要和 action 关联，生成 Verification；只有满足验收才完成新动作流程的 Task。 |
| FR-009 | 取消/撤销阻止尚未进入执行临界点的新动作；已发生的结果与剩余影响显式报告，不能声称已撤销。 |
| FR-010 | CLI/HTTP 使用同一服务；新增协议走版本化路径；现有 v1 请求与响应保持兼容映射。 |
| FR-011 | 审计记录裁决、版本、状态和证据引用；正文及凭据不进入普通日志；错误有 safeToRetry 和恢复原因。 |

## 非功能约束

- NFR-001：固定 DSH 依赖版本不因本切片顺带升级；领域 Schema 不导入上游 SDK 类型。
- NFR-002：单权威节点；事务防止两个批准/执行请求同时消费一次性额度。SQLite 锁竞争有明确错误与重试边界。
- NFR-003：迁移可在旧库副本重演，不破坏已有任务、事件及审批；回滚方案保持新旧数据的实际兼容。
- NFR-004：测量门禁时延和数据库占用并记录基线；本切片不设未经测量的毫秒 SLA。正确性优先于优化。

## 验收

| AC | Given / When / Then | 对应 FR |
| --- | --- | --- |
| AC-001 | 未认证或伪造 owner 的请求到达，查询/提交/审批均按实际 principal 限制；CLI 和 HTTP 得到一致的授权语义 | 001、010 |
| AC-002 | 合法请求准备动作后，审批显示的目标、摘要、版本与实际执行快照相同 | 002、004 |
| AC-003 | 批准后改内容、目标、版本，或令牌过期/撤销，执行被拒且没有新文件 | 003、004、005 |
| AC-004 | 两个并发批准/执行及不同 createdAt 的重传，仅一份产物、一次额度消费；同键异参冲突 | 004、006 |
| AC-005 | provider 请求含路径穿越、符号链接或现有目标冲突，拒绝且专用根外零变更 | 005 |
| AC-006 | 产物已生成后注入账本提交前中断，重启后显式对账找回结果；不创建第二份文件 | 007 |
| AC-007 | 执行器自报成功但文件缺失或摘要错误，Verification 失败，Task 不显示已核验完成 | 008 |
| AC-008 | 取消在执行前、执行中和回执后到达，分别阻止新动作或记录剩余影响；无虚假回滚 | 009 |
| AC-009 | 旧 v1 fixture 与新协议各通过契约，历史 SQLite 副本迁移后记录不丢失 | 010、NFR-003 |
| AC-010 | 在本机专用目录真实创建产物、独立读回，证据含摘要、命令与清理；日志无凭据/正文 | 011、008 |

AC-006 的“重启对账”是显式恢复命令/服务调用，不是 M3 自动持久调度。AC-010 为真实本地 I/O 集成验收，不代表云模型或真实外部服务 live 验收。

## 风险与待决定事项

本切片的可控文件 provider 不证明任意插件的安全。DSH 固定版本工具拦截钩子、Shell 网络与文件隔离能力需要 M1.3 spike；不能在该问题未解决时开放 DSH 外部写入。

认证初期仅单 owner、本地使用，不设计多租户账户系统。候选性能预算待基线后确定，不阻断正确性切片。安全政策、生产身份和发布范围的扩大须另有明确决策。

## 完成定义

[任务](tasks.md) 与 [检查单](checklist.md) 全部满足，证据指向同一源码/产物，负向用例与真实本地操作通过，文档和回滚同步。实现完成不等于 M1 整体完成，M1.3 和三场景外部验收仍需独立规范。
