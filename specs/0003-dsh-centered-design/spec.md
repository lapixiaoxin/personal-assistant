# SPEC-0003 · DSH 中心架构设计与发布

2026-09-25 · 状态：设计交付 Verified（本机 verified_once）；运行时方案 Proposed v0.3。范围是设计与文档发布，不实施 SPEC-0001，不启用新权限。因没有运行时协议、持久化或能力变更，本包合并记录计划、任务和验收；实际建设仍需独立完整 SDD 包。

## 目标、约束与影响

用户要求判断 DSH 作为核心 Harness 的可行性，仅聚焦可能致命的问题；以架构图、流程图为主，覆盖多 channels、多物理设备、多外部能力及合适技术，发布飞书“个人助手”节点下。

| 要求 | 设计落点 |
| --- | --- |
| FR-001 明确 DSH 核心地位 | DSH 唯一 Agent Loop / 规划 / 工具与专家编排；Host 确定性状态与服务 |
| FR-002 图示完整且可读 | 总架构、任务流程、跨端时序、多设备部署、个人资产、扩展进化六图 |
| FR-003 实际可实施 | 固定 SDK/runtime 与源码证据；明确钩子限制、接线、技术取舍和阶段落点 |
| FR-004 保护产品连续性 | 只重点处理真实授权出口、长期任务生命周期、用户个人资产三个问题 |
| FR-005 可接手与发布 | 本地源、ADR、旧设计影响、飞书读回与画板预览、main 提交 |

影响分析：架构 02 中原通用 plugin-host 收敛为 Cordis 接线与 Registry；路线 07 的 M3 接入方式同步。其余授权、资产和受保护验收不变。旧飞书专题不静默重写，新篇标注细化范围，发布清单记录投影差异。新状态名和接口仍是提案，不变更当前 v1 Schema。无源码、测试、依赖或 profile 变更。

## 计划与任务

1. T-01：核验愿景、当前实现和固定 DSH 产物，确定三个必要边界。
2. T-02：编写主设计与 ADR，制作五张 SVG 和一张 Mermaid 时序图。
3. T-03：同步本地架构/路线/索引，核对图文及现状。
4. T-04：专属 XML 草稿检查，飞书创建、全文读回、逐图导出查看。
5. T-05：记录验证与 SOP，检查暂存边界，提交本地 main。

## 验收清单

- AC-001：DSH 与 Host 职责唯一，无第二 Planner 或重复通用 plugin-host。
- AC-002：六图完整，涵盖多端身份、同一 Action 审批、未知结果对账和单权威 Host。
- AC-003：技术选型有当前/未来边界；已验证接口与未验证运行时严格区分。
- AC-004：飞书位于用户指定父节点，XML assessment=passed；读回文本一致，六画板非空且目视可读。
- AC-005：文档链接和追溯检查通过；本次只提交任务相关文档/图源，发布证据不含凭据。

T-01–T-05 的设计、发布与交接产物已完成，AC-001–AC-005 通过；命令、摘要和验证边界见 [证据](evidence.md)。本地提交号由 Git 历史与交付报告记录。设计交付通过不代表用户已接受每项提案或能力已经实现。
