# 超级管家发展路线

状态：2026-10-13。基础实现按 SPEC-0016 验证；后续阶段为 Proposed，不是已启用能力或日期承诺。本路线替代旧 M0–M6 的开发排序；旧验收与安全原则保留。

## 方向

一个自己部署的管家入口，逐步组织自己的 Agent、工具和设备。DSH 持续承担核心；lumi 的投入集中在个性化、能力接入、结果可信和使用体验。现在打地基，不提前接 Dots、Muse，也不围绕未选定的外部产品设计专属代码。

## 交付顺序

| 阶段 | 用户得到什么 | 工程工作 | 进入下一阶段的证据 |
| --- | --- | --- | --- |
| F0 当前基础 | 单机管家、飞书对话入口、可恢复会话 | SDK server、Cordis 通道插件、收发账本、独立个人上下文、精确版本 | 本地契约已通过；还需专用 Bot 真实收发、断线重连、服务器启停 |
| F1 持续可用 | 日常可找、说过的话能接续、失败可查 | 完成部署；配置管理、状态与恢复体验；按真实需要提供个人资产导出/纠正入口 | 真实对话样本、恢复演练、重复消息/未知结果记录、成本和失败分类 |
| F2 先接一种有价值的能力 | 能交付一个可验收结果 | 选一个实际工具或 Code Agent；优先 DSH 原生 Skills/MCP/Agent，缺口才做 adapter | 发现、调用、取消、回执、权限、数据出境和故障用例均通过 |
| F3 组织自己的 Agent 团队 | 一个入口调用多个独立能力 | 基于 F2 的共同需要抽取接口；按需接 ACP/A2A/HTTP；DSH 负责选择和委派 | 同类任务成功率、成本/时延、上下文裁剪；失败不重复副作用、不扩大授权 |
| F4 App 与设备 | 手机/自己的 App 延续同一管家 | 认证 Surface、会话关联、设备身份、可撤销权限；物理动作单独验收 | 跨入口身份与取消一致，设备离线/失窃可撤销，数据不分叉 |
| F5 有证据地变强 | 可量化改进、按规则主动办事 | 经验候选、评测集、受控记忆更新、持久触发、升级与回滚 | 增量收益可测；失败变更停止；权限与受保护验收不由执行 Agent 改写 |

F1 不要求把旧 MVP 整体搬进 DSH。先使用真实入口发现需求，再迁移有价值的个人服务；旧任务 UI 和通用协调代码逐步退役。

## 如何评价能力增长

按业务域、能力版本与风险分层记录：提交量、符合验收的完成量、失败/拒绝/待确认/未知结果、人工接手次数、延迟、模型费用。没有样本时标 `not_measured`，一次成功只记 `verified_once`。

以人的实际投入是否减少为产品依据：包括解释、确认、等待后重建上下文、检查和返工。不能用插件数量、生成文本长度或执行者自报完成代替交付质量。评价与遥测优先保留最少元数据，私人正文不进入普通日志。

可靠性先于自主程度：先证明能完成一种任务，再允许范围内重复执行；先证明故障可停止和恢复，再引入无人值守触发。受信对话身份不自动产生外部业务写权限。

## DSH 持续跟进

每日 CI 和手动 `check:dsh:latest` 发现 release 差异；在隔离工作区同步精确依赖图，验证原生 Session、工具边界、旧保护性契约和外部 bundle，再提交并选择部署窗口。对 alpha 只做专题评估，不自动替换当前 release。

升级不会覆盖运行中的进程，不自动迁移旧会话数据库。切换前停止接收、记录未决结果、备份代码版本和全数据目录，恢复演练后才扩大使用。详见 [上游策略](../upstream-strategy.md)。

## 当前明确推迟

多用户、多主机高可用、通用租约、无限并发调度、语音、具体设备、自动记忆、无人审批的外部写入、自动发布、通用 Agent 市场。只有出现真实使用需求时才增加模块；无需为这些名字预建空目录。

每个增量以独立 spec 定义用户收益、权限、验收、失败处理与回滚。开发和普通 commit/push 沿用已有授权；部署和真实外部业务动作按具体授权处理。
