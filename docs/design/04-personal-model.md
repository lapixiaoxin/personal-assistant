# 个人模型、记忆与主动性

状态：Proposed v0.2 · 2026-09-24。2026-09-25 已由 SPEC-0009 实现显式写入、SQLite 持久化、确认/纠正/撤回/遗忘及粗粒度受控注入；自动抽取、语义检索、完整 ContextBundle 和主动性仍按 M2–M4 逐步实现。

## “懂我”的可操作定义

助手能够在有来源、有时间和适用范围的个人知识上，理解当前请求、补齐必要背景、延续承诺，按用户最近的明确取舍行动，并接受纠正。

懂我不等于窥探更多数据、推断人格标签或永远赞同用户。遇到当前指令与旧偏好冲突时以当前明确指令为准；涉及危险或不可靠前提时说明具体问题；不从少量行为推断健康诊断、情感状态或价值观。

## 个人模型由哪些资产组成

| 资产 | 内容 | 权威与写入方式 |
| --- | --- | --- |
| Identity / Profile | 本人身份、稳定背景、语言、角色 | 用户确认；敏感项单独许可 |
| Semantic Memory | 事实、偏好、习惯、常用约束 | 明确表达可进入已确认规则；推断仅为候选 |
| Episodic Memory | 发生过的事件、任务和互动摘要 | 来自实际事件，附时间、来源与权限 |
| Procedural Memory | 经验证的步骤、SOP、Skill 使用经验 | 成功证据支持，版本与适用条件明确 |
| Social Memory | 人际关系、组织与承诺 | 只记录有依据的信息，尊重第三方隐私 |
| Decision Memory | 当时背景、备选、证据、假设、决定及结果 | 保留“当时所知”，不以事后知识改写 |
| Goal / Commitment | 目标、依赖、截止时间、义务 | 用户意图或确认过的任务产物 |
| Context Snapshot | 当前环境、设备、日程、工作状态 | 有授权的实时观察，附过期时间 |

Personal Model 是这些资产按任务组合的视图，不是一个不断膨胀的 system prompt，也不是单个不透明 embedding。

## 记忆生命周期

`observed → candidate → confirmed → superseded / retracted / expired → erased`

“观察”保存在受限事件或素材层；不是每条观察都值得变成长期记忆。明确“请记住”且范围清楚的低敏信息可以直接确认；由模型总结的偏好、关系和行为规律默认作为候选。

MemoryRecord 保存：

- owner、memoryId、kind、scope、subject、statement；
- sourceRefs、observedAt、validFrom/validUntil、recordedAt；
- confidence、status、version、supersedes、conflictGroup；
- classification、allowedPurposes、allowedRecipients、retention；
- confirmationActor、confirmationMethod、lastVerifiedAt。

置信度仅帮助排序和复核，不产生授权。冲突不直接“取最大置信度覆盖”；先区分场景、时间和来源，再向用户呈现需要决定的矛盾。

## 检索与上下文构建

流程：识别任务用途 → 权限与 owner 过滤 → 候选召回 → 时效和冲突过滤 → 相关性排序 → 内容预算裁剪 → 生成带来源的 ContextBundle。

ContextBundle 标明每个条目的来源、类型、可信程度、过期时间、可转发范围和删除标识。向专家发出的 bundle 默认只包含当前任务所需片段；专家回传的新事实进入候选，不能直接修改权威记忆。

建议优先级：当前明确指令 → 当前有效授权和禁止项 → 与任务相关的已确认记忆 → 新鲜可信的现场事实 → 经过标注的候选信息。数据中的自然语言指令永远不升级成控制指令。

向量召回用于找相似内容，结构化查询用于身份、日期、关系和权限，全文检索用于精确关键词。初期 SQLite 关系表与全文检索足够；测量确有收益后再引入向量服务。索引必须可重建，删除从原始资产传播到派生索引和缓存。

## 记忆纠正与遗忘

用户说“这只适用于工作”“我已经改主意”“删掉这个”时，分别收窄 scope、新增版本或启动删除。旧记录不能继续参与生成，只可在受限历史视图解释过去的决定；删除要求则按保留政策处理。

删除建立 tombstone 并驱逐活跃上下文、检索缓存、向量、图投影、派生 SOP 中的私人实例。备份按约定时间到期销毁；恢复时先应用 tombstone。审计保留删除发生的最小元数据，不保留被删正文。无法从外部收件人或已出境服务收回的数据必须准确说明。

建议初始保留政策：临时传感上下文最长 24 小时，调试正文默认关闭，脱敏执行证据 30 天，确认记忆由用户决定保留期，安全审计保留必要元数据。具体时限是待批准配置，不是当前系统已执行的机制。

## Life Timeline 与知识关系

Timeline 由用户可见事件、重要任务、决定和承诺投影而来；无需全天采集。实体使用稳定 ID，人物重名或身份合并须有证据，错误合并可拆回。事件至少同时保存发生时间和记录时间，避免迟到信息重写历史。

Decision 记录背景、目标、备选、当时证据、假设、最终选择、预期结果、复盘日和实际结果。记录的是决策理由摘要和证据，不保存内部思维链。复盘关注假设是否失效，不把结果偶然好坏简单等同于决策质量。

## 主动性系统

Context providers 接入时间、日历、任务、设备、明确位置和用户主动提供的信息。每个 provider 声明来源、授权目的、采样率、过期规则和数据驻留。环境感知不是默认开启的监控。

触发器先过滤授权、安静时间、重复事件、已处理状态和注意力预算，再按价值与紧迫性决定：

1. 静默准备可逆草稿；
2. 合并到日/周摘要；
3. 需要选择时呈现具体方案；
4. 用户预定义的紧急事项立即提醒。

主动执行需要独立委托，不能从“提醒我”推导“帮我直接发送或购买”。开始时以建议和影子模式验证触发质量，验证合格且获得范围授权后，才自动推进。

## 持久调度语义

调度记录稳定 triggerId、owner、timezone、nextFireAt、误点策略、去重键和 maxCatchUp。设备休眠后不能补发几十次过期提醒；每条规则显式选择 skip / latest / bounded-catch-up。夏令时跳时和重复时段有测试，触发按业务时间窗口判定。

通知也有投递回执、去重和失败重试。任务失败不通过重复推送掩盖；用户已在另一个设备处理的审批立即失效。

## 如何证明更懂你

每次个性化改进必须有可比较场景：减少重复解释、减少错误引用旧偏好、提高承诺召回、减少无关提醒、缩短人工纠正时间。

记忆评测同时看 precision、recall、过期引用率、跨 scope 泄漏率、纠正生效时间和删除完整性。主动性看用户采纳、明确有价值的比例、忽略/拒绝原因与每周打扰次数。单纯记忆条数和通知点击率不作为成功目标。

## 失败与降级

记忆服务不可用时可完成不依赖个人记忆的任务，但必须说明哪些偏好未核验；涉及授权、重要联系人或敏感约束时等待恢复。检索低置信、信息过期或证据冲突时提出最小澄清，继续与该缺口无关的工作。

记忆模块可以替换算法与存储，不能替换用户对“什么被记住、如何使用、何时删除”的控制权。
