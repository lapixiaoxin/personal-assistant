# 安全与数据边界

状态：当前强制原则 · 2026-10-14。

## 当前入口

服务只接受专用飞书应用中配置 owner 的私聊文本。群聊、陌生用户、机器人发送者、非文本和超限内容不进入模型，也不回复。

通道身份只允许对话。当前 DSH profile 默认拒绝文件、Shell、网络、MCP、外部 Agent、设备和业务动作工具；可选个人快照只开放不返回正文的状态工具。

Channel 负责平台认证后才能生成进程内信封；Host 只接收已配置 Channel 的信封，不把普通对象当作远端身份声明。Plugin 负责能力适配但不能绕过 Host 的持久收发语义；`src/domain/` 中的个人数据规则不依赖 DSH 或平台 SDK。目录边界用于减少误接线，不替代进程隔离或恶意插件审计。

## 凭据

- 飞书 Secret 只在权限 `0600` 的私有 JSON。
- 模型 Key 只在未提交的 `.env` 或部署 secret store。
- 个人上下文快照必须禁止 group/other 访问；显式 provider patch 必须是普通文件且禁止 group/other 写入。
- DSH 子进程使用显式环境白名单，不继承 `PA_*`、平台变量、Node 注入参数或无关 Key。
- 普通日志只写固定事件标签，不转储 SDK 参数、消息正文或错误请求。

Provider patch 属于受信运行定义，可能包含 DSH 支持的 `!!js` 表达式。常用且不含凭据的 patch 必须进入 Git 审查；`data/server` 内的自定义 patch 只是实例级覆盖，不能因为被忽略就视为安全。

进程内 guard 只约束受信插件，不是恶意代码沙箱。引入第三方插件前必须评估 OS/container 隔离。

## 数据主权

个人记忆和上下文属于 lumi owner，不属于模型或 DSH Session。建议分级：

- `public`：可公开。
- `personal`：可按明确用途发送给当前 provider。
- `sensitive`：默认不进入云模型。
- `secret`：只存 secret store，不进入 prompt。

个人上下文是数据，不是指令或权限。纠正快照不会清除既有 DSH Session 历史或备份，需单独 retention 机制。

## 可靠发送

输入先落盘；回复发送前先保存意图。平台没有确认回执时标 `unknown`，禁止自动重发。模型运行中断标 `interrupted`，禁止自动重放。

流式模式的两条消息分别保存目标与回执，更新只作用于已知卡片。进度展示固定公开阶段说明，不发送模型内部 reasoning、原始工具参数或异常正文；正文按 text 块投影。取消、失败和重启必须把已知卡片标为未完成并结束流式状态，不能用已发送占位卡片的回执冒充完整回答已送达。

原生 COT 进度复用相同边界：只投影固定阶段文案和实际 DSH 工具事件，工具名称通过允许表展示，未知名称使用通用标题，不发送工具参数、结果正文或推理原文，不为折叠层级伪造工具调用。创建 API 无已确认幂等契约，未知创建禁止重试和自动降级补发；增量追加也不重放，历史不确定保留证据。仅对已知 cot_id/message_id 设置终态，正文收尾不依赖进度追加成功。

`/cancel` 和 `/stop` 只取消生成与排队输入，停止按钮产生的命令仍须通过原有身份验证。未来任何外部副作用都必须单独记录动作、参数摘要、授权、幂等键、平台回执和核验；不能因聊天被取消而声称副作用撤销。

## 新能力准入

每个工具、Agent 或设备接入必须回答：

1. 谁经过何种认证调用？
2. 最小数据和用途是什么？
3. 可读取/写入哪些对象？
4. 参数变化是否重新授权？
5. 超时、取消和重试如何处理？
6. 远端成功、本地断开如何对账？
7. 什么证据才表示用户结果完成？
8. 如何停用、备份和回滚？

缺少稳定幂等键或查询接口的副作用不得无人值守重试。模型置信度不能补齐缺失授权。

## 运维

停止服务后再做一致备份，覆盖完整 `data/server` 与匹配代码版本。不要只复制 SQLite 主文件而遗漏 WAL。代码回滚不撤销现实世界效果，旧 DSH 不直接写新版本 Session。

当前未完成磁盘字段级加密、跨主机 fencing、自动 retention 和长期故障演练，不得宣称具备这些保证。
