# 安全、授权与数据主权

状态：Proposed v0.2 · 2026-09-24。安全要求分阶段实现；当前 MVP 的限制见工程基线。

2026-10-13 / SPEC-0016：新 server 只接受专用飞书应用的单 owner 私聊文本，回复绑定原消息；接入对话入口不授予其他业务动作权限。默认工具 guard 拒绝文件、Shell、网络和委派，可选个人上下文只提供状态工具。平台凭据保存在私有 JSON，由受信插件读取，不进入模型可见工具或普通日志。

新收件箱先保存输入与发送意图，未知结果不自动重发；恢复时不重放中断的 DSH 输入。当前没有真实飞书验收、恶意插件 OS 隔离、跨主机恢复或磁盘加密证据。旧 Action 门禁原则继续有效，但旧动作能力尚未接入飞书。以下长期控制目标不能当作当前已实现事实。

## 受保护资产与威胁边界

保护对象是个人记忆、账户凭据、工作与生活资料、真实世界动作、资金和设备，以及助手自身的代码、策略与验证体系。

外部网页、邮件、附件、Skill 文本、远端 Agent 回答和工具结果均视为不可信数据。即使来源是熟人，也不能把其中的指令当成用户授权。不可信插件和被诱导的执行 Agent 应无法绕过动作代理访问生产凭据。

主要威胁及对应措施：

| 威胁 | 强制控制 | 验证方式 |
| --- | --- | --- |
| 提示注入诱导发信或泄露记忆 | 数据/指令分离、最小上下文、动作门禁和出境限制 | 恶意文档诱导测试 |
| Agent 从 Shell/curl 绕过工具门禁 | OS 隔离、默认禁网、代理凭据、不挂载生产秘密 | 直接连接与凭据探测负向测试 |
| 请求体冒充用户或审批者 | 认证入口派生 principal，服务端对象归属校验 | 越权读取和审批测试 |
| 审批后收件人、金额或资源变更 | 参数摘要、资源版本、有效期、执行前复核 | 参数替换和 TOCTOU 测试 |
| 重试导致重复发送/支付 | 稳定幂等键、动作日志、远端回执和对账 | 外部成功后断电测试 |
| 插件供应链被替换 | 来源、锁版本、摘要、审查、最小安装脚本权限 | 摘要不符拒绝加载 |
| 自我升级降低门槛 | 独立验证器、受保护策略、发布签名 | 修改验收/策略的候选被阻止 |
| 记忆污染与跨域泄漏 | 候选确认、scope、来源、owner 和用途过滤 | 冲突、删除、越界召回测试 |

## 身份与委托

Owner 是数据和助手的所有者；Principal 是当前操作主体；Agent 是可被授权的执行主体；Device 是具备身份与能力的节点。这些不能混成一个字符串。

后续所有入口以 token 或本地受信凭据认证，服务端派生 owner 和 principal。Loopback 只降低暴露面；本地恶意进程、浏览器跨站请求和同机其他用户仍需要处理。远程接入前完成 TLS、来源限制、认证、对象级授权、限流和凭据撤销。

DelegationGrant 最小字段：授予者、被授予主体、任务/目标范围、允许动作、资源与对象集合、用途、数据出境范围、费用和次数上限、开始/结束时间、是否可再委派、撤销 epoch。

子委托只能缩小集合与额度；所有子任务消耗同一根委托预算。凭据存放 secret store，由受信代理按操作短期使用；不写入 prompt、日志、Git 或 Skill。

## 权限层级与实际判定

| 层级 | 用户可理解的含义 | 例子 |
| --- | --- | --- |
| P0 Observe | 读取指定资源 | 查看已授权日历 |
| P1 Suggest | 分析并提出方案 | 建议会议准备清单 |
| P2 Prepare | 生成可审阅草稿 | 起草邮件但不发送 |
| P3 Confirmed Action | 执行一项具体确认动作 | 发给已确认收件人的固定正文 |
| P4 Policy Delegation | 在范围政策内重复执行 | 在指定文件夹按规则归档 |
| P5 Goal Delegation | 在目标边界内自主分解推进 | 跟进项目资料，超出范围再请求 |

层级表达交互方式，不是安全判定的单一数字。读敏感数据仍可能高风险；本地写入也可能破坏重要文件。动作按影响对象、可逆性、金额、外部可见性、数据敏感度和物理风险独立判断。

有效权限 = 用户委托 ∩ 执行主体权限 ∩ 能力已验证范围 ∩ 设备/环境权限 ∩ 数据用途政策 ∩ 当前预算。任何明确 deny 优先。

## 自动执行的边界

首批可自动化范围为低敏只读、隔离目录内草稿、可恢复的本地整理。对外消息、日历邀请、修改他人共享资料等动作，需要具体授权，后续才按业务规则授予重复执行权。

大额资金、重大合同、重要关系表达、不可逆删除和高风险物理行为保持每次明确确认。范围授权不可用模糊“全权处理”覆盖未明确的金额、对象与行为。未来是否放宽必须是用户修改政策的决定。

任务已经明确授权的可逆步骤可继续；不因内部实现换了一个工具反复询问。需要确认时应给出已准备好的对象、内容、影响、成本、有效期与替代方案，让用户作一次具体决定。

## DSH 与执行沙箱

DSH 自身有工具执行扩展点和沙箱/审批机制，但上游明确处于 developer preview，并说明不能作为不可信工作负载的唯一安全控制。本项目必须在固定版本上验证实际阻断效果。

目标执行路径：受限 executor → Action Broker → Policy → 持久动作意图与预算 → 受信 Connector → 外部系统。DSH hook 用于把动作送往 broker；若仍允许执行器拿生产 token 直接使用 Shell、网络或文件系统，就没有形成完整边界。

M1 能力验证以“恶意或被注入的执行路径也绕不过”作为准入条件。不能拦截的任意工具保持禁用，或运行在无生产凭据、限制网络和文件挂载的隔离环境。进程内插件只适合受信实现；不可信代码要有 OS/container/VM 级隔离。

沙箱声明要具体：运行用户、目录挂载、网络出口、可见环境变量、进程启动权限、CPU/内存/磁盘/时限。通过测试后记录平台和版本；不能笼统写“已沙箱化”。

## 数据主权与驻留

建议分级：public、personal、sensitive、secret。默认 secret 不进入模型；sensitive 本地处理或使用明确授权的服务。Context Broker 依据任务用途和接收者裁剪，不把整份个人模型发送给垂类 Agent。

加密覆盖传输、备份和敏感持久数据。模型商保留策略、日志用途和地域需要记录在 provider 清单；“本地优先”不等于调用云模型时数据没有离开设备。

用户可以查看、导出、修正和删除个人资产。导出包括稳定 ID、版本、来源和关系，不包含可直接滥用的活跃令牌。密钥轮转与数据迁移分开；账号或设备失窃时先撤销身份，再恢复可用数据。

## 审计与可观察性

记录谁以什么授权、用哪个版本，对什么对象，何时做了什么，结果由什么证据确认。保留结构化行动理由摘要，不保存内部思维链。

日志默认不含 secret、完整工具正文、私密联系人细节。证据正文独立保存并有 ACL、retention 和脱敏视图。审计元数据追加写入；未来可通过摘要链和外部锚点检测篡改，但仅本地摘要链无法防止具有全盘写权限的攻击者重写全链。

关键动作账本不可写时禁止新副作用；可选统计不可用时可降级并告警。安全撤销和 kill switch 的执行不应依赖 LLM 服务在线。

## 停止、恢复与灾难处置

全局停止先禁止新动作、撤销未消费令牌、停止调度，再取消在途任务。已经送达的消息和已经执行的设备命令不能被“取消任务”自动收回，必须核验并告知剩余影响。

备份至少覆盖 SQLite 一致快照、产物索引、策略版本、插件锁和恢复元数据；密钥独立备份。M3 建议目标 RPO ≤24 小时、RTO ≤1 小时，需要恢复演练才能承诺。动作回执和幂等日志恢复优先于重新执行。

受控升级使用代码版本切换及兼容数据迁移。数据库不可逆变更时，旧版本可能不能直接运行；采用 expand/contract、迁移前快照及前向修复计划。回滚不承诺撤销现实世界副作用。

## 安全推进门槛

M1 前不扩大到真实外部写入；M3 前不无人值守重试有副作用任务；M4 前不开放多设备远程写入；M5 前不由开发 Agent 自主发布；M6 的设备必须另做物理风险分析和独立急停。

安全机制本身也需要可用性和恢复测试：撤销按钮有效、审批不会无限打断、合法范围任务能完成。可靠性与用户掌控感共同决定信任。
