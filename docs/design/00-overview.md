# 超级个人助手：长期设计总纲

版本：v0.2 · 2026-09-24 · 状态：Proposed（供审阅，尚未作为运行时能力实现）。

## 一句话定调

建立一个属于你的、持续存在的个人智能体：它理解你的目标和取舍，积累可修正的个人记忆，在授权边界内组织各种专业能力，把事情推进到有证据的结果，并通过可验证的经验和工程变更持续进步。

“最懂我”是核心资产，“真正能干活”是交付标准，“自主进化”是建设方式。三者共同受你的控制权约束。

## 这次方案解决什么

原始《超级个人助手》已经确定长期愿景。本方案将其落到五个可以持续建设的支点：

1. **个人连续性**：身份、记忆、目标、承诺和授权属于个人助手，换模型、设备、执行引擎时仍然存在。
2. **可靠交付**：把 Goal、Task、Run、Action、Artifact、Verification 分开；模型结束生成不等于任务完成。
3. **开放组合**：业务能力、推理策略、记忆实现、模型和入口都通过有版本的接口替换；先模块化单体，再按需要拆进程。
4. **有界自主性**：能力、熟练度、主动性和授权分别管理；信任增长不自动授予权限。
5. **工程复利**：每次有证据的成功可以形成候选 SOP；每次升级都可追溯到规范、测试、发布与回滚证据。

## 关键决定

| 决定 | 为什么 | 当前落点 |
| --- | --- | --- |
| 保留现有 TypeScript / pnpm / SQLite / DSH adapter | 当前结构已有可用边界，改造成本集中在缺失的控制语义 | 增量演进，不重写 MVP |
| 学习 DSH 的服务契约、声明依赖、可撤销注册 | 让实现可换、插件可卸载、依赖可检查 | 暂不在 Core 内引入 Cordis |
| 保留小型可信控制边界 | 可替换实现不意味着任意插件可绕过授权、审计和发布验证 | 逻辑边界先确定，隔离逐步落实 |
| 先完成动作门禁和结果证据 | 当前任务级审批无法约束执行中临时产生的每个动作 | M1 优先于外部写入、自治和多端 |
| 先做三个实际工作闭环 | 用重复的真实任务证明省心，再增加能力种类 | 会议准备、资料研究、仓库变更 |
| 独立建设进化平面 | 开发 Agent 可生成变更，但运行中的助手不能直接替换自身 | SDD + 隔离工作区 + 独立验证 + 发布控制 |
| 权限按具体委托生效 | “越来越信任”不能变成全局无限权限 | 范围、对象、次数、时限、预算、撤销 |

这里的“可信控制边界”是目标设计。当前进程内模块、提示词和本地数据库尚不构成对恶意插件的安全隔离。

## 两条闭环，一份个人资产

**办事闭环**：理解目标 → 确定结果与限制 → 构建上下文 → 选择能力 → 准备动作 → 策略检查 → 执行 → 核验 → 汇报 → 候选经验。

**进化闭环**：发现缺口 → 写规范 → 建立基线与验收 → 隔离开发 → 独立验证 → 受控发布 → 观察效果 → 保留或回滚 → 更新 SOP。

身份、目标、记忆、授权和证据由个人助手管理。执行 Agent 只领取任务所需的最小上下文和短期权限。进化 Agent 只领取变更所需的代码、脱敏案例和测试权限。两个闭环都不能自行修改用户价值判断或扩大授权。

## 成功标准

第一性指标是：**在结果质量不下降、权限边界不被突破的前提下，为完成同一个结果减少了多少人的投入。**

衡量人的投入时，要计算解释需求、等候后重新接手、确认、检查、返工和事故修复的时间。自主完成率必须按业务域、风险、版本和任务难度分层；拒绝高风险请求不应被误记成能力失败，也不能通过排除失败任务抬高成功率。

长期个人放大指数可以作为多维仪表盘，暂不合成一个虚假的总分。时间节省、认知负担、目标推进、决策质量和生活体验分别记录。

## 近期实际顺序

先固化事实与规范（M0），再把动作级执行与可核验结果做扎实（M1），随后让记忆、目标和会话持续存在（M2），之后接入持久调度与专家能力（M3），再扩大到多端和有限自主进化（M4、M5）。物理世界和更广泛的生活托管属于长期 M6。

SDD 和 SOP 从今天开始；它们不等待 M5。M5 指助手能在既定发布政策内自主完成工程升级，和今天用 Code Agent 开发是两个成熟度。

## 尚待实际证据决定的事项

初始阈值、预算和时间估算是建议，不是测量结果；见里程碑及评测文档。实际设备平台、云部署供应商、远端 Agent 协议版本、图数据库和向量数据库选型，均在出现真实需求后通过专项规范确定。现在冻结的是边界、数据所有权、兼容和验收原则。

本次交付不宣称已实现动作沙箱、长期恢复、自动记忆或自主发布。现有业务源码保持现状，下一步实现从 [M1 首个变更规范](../../specs/0001-action-boundary/spec.md) 开始。
