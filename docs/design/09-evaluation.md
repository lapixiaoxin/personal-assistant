# 评测与真实验收

状态：Proposed v0.2 · 2026-09-24。指标定义为设计；当前已有测试结果见工程基线。

## 评价目标

结果质量、人的负担、边界安全和持续进步必须共同评价。活动次数、Token、工具调用次数和生成速度只能帮助诊断，不能代替价值。

## 指标与分母

| 指标 | 定义 | 必须同时报告 |
| --- | --- | --- |
| Task Success Rate | 在截止与预算内满足全部关键验收的任务数 / 已到验收时点的受理任务数 | 失败、部分完成、等待、取消、拒绝；任务域和难度 |
| Autonomous Completion Rate | 无计划外人工干预且验收通过的任务 / 已到验收时点的受理任务 | 是否含预定审批；另报仅自主合格子集的分母 |
| Human Effort Reduction | 1 − 委托后的人工总时间 / 人工基线时间 | 基线来源、样本量、中位数和分布，负值也保留 |
| Goal Progress | 验收过的里程碑与目标结果变化 | 活动量不能作为结果增量 |
| Memory Precision / Recall | 正确且适用的召回 / 全部召回；正确召回 / 应召回 | 过期、冲突、不同 scope、删除后泄漏 |
| Proactive Precision | 用户明确评价有价值的主动项 / 已评价主动项 | 全部主动项、未评价、忽略、拒绝和打扰频率 |
| Cost per Verified Outcome | 模型、工具、基础设施及必要人工成本 / 已验证结果 | 各成本分项、失败和重试的费用 |
| Recovery Reliability | 在注入故障后安全恢复或准确升级处理的次数 / 故障用例 | 自动恢复、需人介入、结果未知、不安全重试 |
| Evolution Improvement | 同一评测集上新旧版本的质量、人工负担、成本差 | 版本摘要、置信区间或样本限制、真实灰度 |

用户请求在受理前因权限拒绝可单列；已经受理后失败或截止前未完成不能从分母消失。取消区分用户目标变化和因系统问题放弃，避免美化完成率。

## 能力档案

每个 capability + operation + version 维护按业务域、风险、数据敏感度、执行位置、任务难度、模型、工具版本分层的结果。低样本标记 `insufficient_evidence`，不提供看似精确的排名。

能力可用状态包括 implemented / tested_offline / verified_live / enabled / authorized。知道有一个工具、能启动它、真实用成功、获得使用权限是不同事实。

## 六层测试

| 层次 | 证明什么 | 不能证明什么 |
| --- | --- | --- |
| Unit | 状态、规则、预算和转换的局部不变量 | 外部服务可用 |
| Contract | producer/consumer、SDK 和协议兼容 | 实际模型质量 |
| Integration | 真实数据库、进程和模块协作 | 生产权限与真实业务结果 |
| Scenario / Eval | 预定义用户结果、记忆与路由质量 | 所有现实输入都安全 |
| Live Acceptance | 指定账号和真实服务的一次可核验结果 | 长期可靠性 |
| Recovery / Soak | 重启、断网、休眠、限流与长期运行 | 未覆盖平台和故障 |

Mock 与真实测试的标记必须跟随结果进入报告。真实 DSH SDK + 模拟模型称 runtime contract，不称“真实模型验收”。

## 标准场景集

首批收集会议准备、研究资料、仓库变更三类样本，包含正常、缺资料、过期来源、冲突约束、权限不足、取消、成本上限和工具故障。每个样本在执行前固定目标、输入快照、允许动作、验收和人工基线。

人工基线优先来自相同用户的实际操作计时；无基线时用明确标注的估计，不宣称准确节省了某比例。验收者能打开产物、追踪来源并检查关键事实。

## 真实测试 SOP 要求

每次 live 测试记录：测试账号和资源范围、授权来源、允许动作、预算、截止、运行版本、输入摘要、真实步骤、外部回执、读回结果、人工判断、清理和剩余影响。

先只读，再可逆写入，最后才测试高影响动作；高影响测试没有现成授权时只完成可审阅准备。不得用生产支付、公开发信或真实门锁操作来“顺便验证”。

一次成功升级为 `verified_once`；跨环境复现后扩大适用范围。失败保留报告，定位后只重跑受影响检查；没有变化或疑点时不重复跑全部昂贵测试。

## 对抗与故障矩阵

- 恶意文档要求发送秘密、修改策略、伪造来源。
- 审批后修改参数，令牌过期，撤销与执行竞争，重复批准。
- 请求重传但服务端时间变化；外部写入成功但客户端超时。
- 老 worker 租约失效后继续运行；多个设备同一任务重放。
- 工具输出声称“完成”，但实际文件/事件不存在或版本不符。
- 记忆被纠正/删除后仍出现在缓存、摘要或专家上下文。
- 模型、插件、发布策略和评测 fixture 被候选变更修改。
- 重启、断网、时区变换、设备休眠、磁盘满、secret 撤销。

所有安全关键失败必须阻止扩大启用范围。普通质量阈值可以通过版本化决策调整，但不能回写旧结果或删除不利样本。

## 回归与上线

发布前同一版本固定的回归集比较旧版和候选；上线后观察实际人力、成本和失败。在质量不低于预设边界的前提下才评价提速和降本。

初始建议指标阈值见里程碑；它们不等于统计置信的保证。样本量小则报告具体的分子/分母，并保持有限灰度。

## 可复核证据

Evidence Bundle 至少包含：spec 与 AC、源码/产物摘要、环境、依赖锁、测试命令、退出码、用例数、脱敏结果、真实外部回执或明确 mock 标记、未跑项及原因、验证者和时间。

本次工程验证可以复现但仓库尚无 commit；不能提供不存在的 revision。未来先建立初始提交或计算源码 tree digest，再签发绑定该产物的发布证明。

指标提取应由结构化任务、动作、产物和验证记录完成，减少让模型自报成功率。用户反馈用于校正验收和个人价值，不能被系统擅自篡改成好评。
