# 升级、停止与回滚规程

状态：planned · 2026-09-24。现有 DSH 固定版本策略可读 [上游策略](../upstream-strategy.md)；自动发布、灰度、备份恢复和版本迁移尚未按本规程实现。

## 前置

变更在独立 feature branch/checkout；base、candidate、lockfile、构建和评测摘要明确。无初始 commit 时先按授权保存基线，不能引用不存在的回滚版本。备份必须使用 SQLite 一致性备份机制或停写后复制，不能只复制活跃 WAL 数据库主文件。

列出受影响插件、协议、数据结构、密钥权限和在途任务。确定先前可用产物、兼容窗口、恢复时间目标和恢复点目标；数值由具体 spec 给出并演练，不凭空承诺。

## 升级门禁

1. 对齐上游 SDK/runtime/mock 精确版本，检查变更和供应链来源。
2. 跑相关契约、完整必要检查、权限负向及真实可逆任务。
3. 绑定受保护验收与候选产物，Verifier 独立取证。
4. 检查迁移 expand/backfill/contract 顺序；先证实旧版本仍能读取兼容结构。
5. 在已有发布授权内停止新派单，drain 或安全取消在途任务。
6. 灰度特定任务范围，观察质量、成本、人工接管和权限事件。

## 停止及恢复

安全不变量失败立即停止新动作；普通回归按发布前固定阈值决定。冻结新版本路由，保存失败证据，对账全部 executing/outcome_unknown 动作，再切回兼容的旧产物。

如果旧程序不能读取新数据，先停止服务并使用已演练恢复路径；不得机械执行旧二进制。外部效果只能对账/补偿，不能随代码回滚“消失”。

恢复后读取历史任务、确认审批撤销仍有效，执行一个真实可逆任务并读回；只有这些成功才记录 restored。证据包含数据水位、遗漏或重复对象、恢复耗时和剩余影响。

## SOP 更新

成功升级只更新已验证步骤。失败说明归入 evidence/incident；上游变更导致旧 SOP 不适用时降级状态。发布政策和受保护评测变化单独审查，不能由 Builder 自己放宽。
