# 真实任务验收规程

状态：planned · 更新于 2026-09-25。当前仅 `local-artifact/1` 具备参数门禁、单 owner 认证和独立核验；真实外部 connector 与 DSH 工具旁路尚未验收，不能按此文宣称已具备安全的外部写入。以下是后续 connector 必须满足的操作要求，不是可直接运行的命令。

## 前置

绑定 spec/AC、精确源码与依赖版本、测试身份、专用资源、具体权限和预算。先列出预期产物和独立读回方式。检查授权来源已覆盖动作；缺少授权时完成草稿和可审阅测试包，等待该具体动作的许可。

真实模型可以使用专用账号和脱敏输入；密钥放 secret store/环境，不写入证据。每一外部 connector 先通过只读验证，再验证可逆写入。

## 操作

1. 保存输入快照、预期结果、允许目标和人工基线。
2. 通过助手正式入口提交，记录 Task/Run/Action ID；不得从旁路工具完成任务后冒充助手执行。
3. 核对 ActionProposal、参数摘要和审批展示的一致性。
4. 在允许范围执行一次，保留业务回执；发生超时/断线先进入结果未知流程。
5. 使用独立读取通道确认对象、字段、版本、产物摘要和预期效果。
6. 让验收者检查结果质量与来源，并计入确认、核查、返工的人力。
7. 清理本次新建对象，读回确认清理；不可逆影响写清并保留回执。

## 三个起步场景

会议准备：从测试日历及已授权文档生成带来源 brief，不通知真实参会人。研究：对固定来源生成带证据报告，标明时效和不确定性。仓库变更：在独立 checkout 产出 patch，执行真实检查，默认不合并或部署。

M1 可逆外部写入样例是专用测试日历的无参会人事件，或专用文档目录的测试草稿；具体选择由 connector spec 锁定，不能默认为用户已授权任意测试对象。

## 停止和异常

越界、参数不符、撤销失效、预算耗尽、秘密泄漏、来源不足或结果未知都停止新动作。对账读请求同样受权限约束；无可用幂等键/查询方式时不自动重发。

## 证据与晋级

将命令、资源脱敏引用、外部回执、读回、人工判断、清理结果和失败写入 evidence。一次成功标 `verified_once`；跨环境和边界复现后才扩大 SOP 的适用范围。30 个任务等指标是设计建议，不是本次已有成绩。
