# ADR-002：动作出口强制检查，自主开发与发布分权

状态：Proposed · 2026-09-24。关联：设计 03/05/06、SPEC-0001。

## 背景

当前风险判断针对任务文本，工具事件仅记录。任务审批不能约束执行中生成的参数；插件可替换也不能意味着授权和核验可以被插件关闭。未来 Builder 能改代码，必须防止其用自报成功或放宽验收获取发布权。

## 备选与建议

仅靠提示词和任务审批成本低，但不能阻止工具绕过。每个工具自行实现安全逻辑易产生遗漏。建议以统一 Action Broker 对具体参数、目标、权限、预算进行确定性检查；执行器的文件、网络和凭据由隔离/执行代理约束。

立即在当前进程内加一个接口并不能形成恶意插件隔离，因此先验收一种受控动作，逐步证明 DSH 工具接线和 OS 限制。无法证明阻断的能力保持未启用。

进化独立为提案、Builder、Verifier、Release Controller、Observer。低风险配置与插件在未来既定政策下可以自动发布；授权根、受保护评测、数据出境和核心控制变更需要独立决策。

## 后果与失败语义

Action 与 Authorization 绑定规范化参数摘要、版本及撤销 epoch；执行前重验。远端成功、本地丢回执时标 `outcome_unknown`，先对账，不盲重试。代码回滚不能撤销已发消息或已付款，补偿必须另有授权。

初期增加显式对象和证据成本，但避免后期把审批、审计、预算分别嵌入每个入口。普通插件不能修改可信门禁；门禁实现本身允许通过受保护发布升级。

## 验证和撤销条件

摘要变化、过期/撤销、重复批准、网络/文件绕过、未知结果、伪造完成、Builder 改验收根均有负向用例。发布绑定候选源码及产物摘要，回滚后有真实可逆任务验证。

允许替换具体 broker、隔离技术和发布工具；不能通过撤销本 ADR 默许无证据执行。若体验过度打扰，优化委托粒度和预授权范围，不删除控制语义。
